# 两种延时函数介绍
FreeRTOS 提供了两种延时函数：`vTaskDelay()` 和 `vTaskDelayUntil()`。这两种函数的主要区别在于它们的延时方式：

1. **相对延时函数 `vTaskDelay()`**：这个函数会让当前任务进入阻塞状态，延时的时间长度由参数指定，单位是系统时钟节拍周期。延时时间是从调用 `vTaskDelay()` 后开始计算的相对时间。例如，如果调用 `vTaskDelay(100)`，那么从调用 `vTaskDelay()` 后，任务进入阻塞状态，经过 100 个系统时钟节拍周期后任务解除阻塞。如果调用 `vTaskDelay()` 函数的任务在执行过程中被更高优先级的任务或者中断所打断，那么调用 `vTaskDelay()` 函数的任务将会受到影响，此时将不能保持一个固定的时间间隔运行。

2. **绝对延时函数 `vTaskDelayUntil()`**：这个函数会让任务以固定的时间间隔重复运行。调用 `vTaskDelayUntil()` 函数时，绝对延时的时间包含该任务本身的执行时间，以及任务被打断的时间。例如，任务执行所用的时间，以及任务被打断占用的时间，都属于绝对延时的时间范围内。任务执行过程中被短暂打断也不会影响绝对延时，从而保证任务能够以设定的时间周期重复运行。

# 用法
**`vTaskDelay()`**：
```c
vTaskDelay(50);
```
这样该任务阻塞50ms。
**`vTaskDelayUntil()`**：
```c
TickType_t pxPreviousWakeTime = xTaskGetTickCount();
    while (1)
    {
        OLED_Buf_Show();
        xTaskDelayUntil(&pxPreviousWakeTime,50);
    }
```
需先用`xTaskGetTickCount`记录当前时间，然后可进行绝对延时。但是如果任务不是最高优先级，则仍然能周期性的将任务解除阻塞，但是解除阻塞的任务不一定能获得CPU权限，因此任务主体代码也不会总是精确周期性执行。
